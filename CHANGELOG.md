# Changelog

## 1.4.0 (2026-11-12)

- **Dev excuses** bubble: a white smiley on pink, the only pink bubble. A click writes a random developer excuse in the app in front, never the same one twice in a row: some forty in English and forty written for French developers, in the language of the plugin. The excuse goes through the clipboard (copy, then Cmd+V or Ctrl+V), and the clipboard comes back as it was a moment later: everything on macOS, text only on Windows. On macOS, typing needs the Accessibility permission for Logi Plugin Service; without it, the first click asks macOS for it, and the excuse stays in the clipboard with a notification that shows it. The trigger file takes `excuse`. The Windows path has not been tried on a real Windows machine yet: reports are welcome.

## 1.3.0 (2026-11-12)

- **Pictograms from GitHub's Primer octicons.** The bubbles draw them from SVG at the size the ring asks for, so their edges stay smooth in Options+: the arrows of Push and Pull keep their tips, the pull request icon is GitHub's own, and the line of Commit meets its circle. The pictogram sits a little higher above the number. The README images are drawn again.
- **Windows: the project bubbles follow File Explorer**, as they follow the Finder on macOS. The folder of the front File Explorer window becomes the current project; with tabs, the window title tells which one is in front. `followFinder` covers both. Not yet tried on a real Windows machine: reports are welcome.
- **macOS: following the Finder starts no process.** The plugin asks macOS which app is in front instead of running `lsappinfo` twice every two seconds, and runs `osascript` only while the Finder is in front.
- **The installers offer GitHub CLI**, which the GitHub bubbles, the GitHub inbox and `ci-watch` need. When `gh` is missing, `install.sh` offers `brew install gh` and `install.ps1` `winget install GitHub.cli`, when Homebrew or winget is there. When `gh` is installed but signed out, both offer `gh auth login`. Enter means yes, a refusal never stops the install, and `--yes`, `--only` or no terminal only print the advice.
- README: a demo of the ring at the top, the ring image next to the bubbles table, a step to give the Finder (or File Explorer) a ring of its own, and the icon reset only for a bubble that shows its name.

## 1.2.0 (2026-11-12)

- **The CI bubble reads every check of the latest commit**: all the workflows of the push, and the services that report to GitHub (Vercel, Netlify, CircleCI and other check runs or commit statuses). Red as soon as one fails, running while one still runs, green when all passed. It comes with the issue and pull request counts, in one GitHub call instead of three. For two minutes after a push (from the bubble or a terminal), GitHub is polled every 15 seconds, so checks that end between two regular polls still vibrate. A click opens the failing check.
- **Agent bubbles open the terminal you use.** The shell integration notes the terminal of each prompt, and `agent.terminal: auto` opens that one: Terminal, iTerm, Ghostty 1.3 or later, Warp (through a tab config of its own), and on Windows Windows Terminal or a PowerShell window. From the terminal of VS Code, which cannot be driven from outside, Terminal opens. `agent.terminal` and `agent.launch` still win when set; `ghostty` and `warp` are new values. Warp and Ghostty are not tested yet.
- **Coding agents vibrate only after a turn of 30 seconds or more**, like long commands in the terminal: a quick answer while you watch stays silent. The installers add one hook per agent that notes when a turn starts (`UserPromptSubmit`, `BeforeAgent`, `userPromptSubmitted`). `MX_TURN_SECONDS` changes the threshold, `0` vibrates at every turn. Permission requests, questions and failed turns always vibrate. Codex asks once more to trust its hooks (`/hooks`).
- **The installer writes where your shell reads.** zsh: `${ZDOTDIR:-~}/.zshrc`, ZDOTDIR included when it is set in `~/.zshenv`. bash: `~/.bash_profile`, or the `~/.bash_login` or `~/.profile` already there, which the login bash of macOS reads (`~/.bashrc` alone is never written again). fish: a new integration, `shell/mx.fish` (long commands, `buzz`, `ci-watch`, project tracking), loaded from `~/.config/fish/conf.d/mx-dev-kit.fish`. Any other shell: the installer says it has no integration for it, writes nothing and gives the line to add by hand. The uninstaller removes the line from each of these files.
- **Windows: one profile for every host.** `install.ps1` writes the line to `profile.ps1` (CurrentUserAllHosts) of Windows PowerShell and, when it is installed, of PowerShell 7, in Documents wherever Windows keeps it (OneDrive included). The console, Windows Terminal and VS Code all load it. A profile that already loads the integration, by hand or from an earlier version, is not given a second line: the block of an earlier version moves from the host profile to `profile.ps1`. `uninstall.ps1` removes it from all of them.
- **Windows: vibrations without DNS, and a prompt that never waits.** The PowerShell hooks, `haptic.ps1`, the terminal integration and the watchers go through the `curl.exe` of Windows 10 and 11 with `local.jmw.nz` resolved locally, as on macOS: they work offline and behind resolvers that block names pointing to `127.0.0.1`. The hooks and the prompt start it without waiting.
- **Tests of the PowerShell scripts.** Pester tests (`tests/powershell`) run the installers, the profiles, the hooks, `haptic.ps1` and `mx.ps1` in Windows PowerShell 5.1 and PowerShell 7, on Windows, at every push and pull request. The shell tests cover the new installer cases and the fish integration.
- README: the trademark paragraph moves to Credits.

## 1.1.2 (2026-11-11)

- **Commit safeguards.** The Commit bubble refuses, without touching the repository, during an unfinished merge, rebase, cherry-pick or revert, when new lines hold conflict markers, or when a secret file that is not ignored would be committed (`.env`, `*.pem`, `*.key`, SSH private keys...). A notification names the files. On `main`, `master` or the default branch, it asks for a second click within 5 seconds.
- The background git calls no longer take optional locks (`GIT_OPTIONAL_LOCKS=0`), so they never hold `index.lock` during a commit or a rebase in your terminal.
- README in French, `README.fr.md`.

## 1.1.0 (2026-11-10)

- **The installers install the Haptic Web Plugin.** With the agent haptics or the terminal integration, `install.sh` and `install.ps1` offer to install the [Haptic Web Plugin](https://github.com/Fallstop/HapticWebPlugin) by Jasper M-W (MIT license), which their vibrations need: one question, Enter meaning yes. `--yes` and `--only` install it without asking, `--no-haptic-web` / `-NoHapticWeb` skip it. The package comes from the latest release of that project and is checked (`name: HapticWeb`) before it goes to the plugins folder of Logi Plugin Service, which is asked to load it. A Haptic Web Plugin already installed, from the Marketplace or elsewhere, is never replaced. Any failure leaves the rest of the installation as it was and falls back to the Marketplace instructions.
- The uninstallers leave the Haptic Web Plugin in place, since other tools may use it, and say so.

## 1.0.0 (2026-11-10)

First public release.

- **Actions Ring plugin**, `MxDevKit.lplug4`, prebuilt, one file for macOS and Windows: double-click it with the plugins manager of Logi Options+ open. Bubbles for the project and its branch, issues, pull requests, CI, vulnerabilities, commit all changes, push, pull, coding agents, review requests, GitHub inbox and a focus timer (25 minutes, then a 5-minute break). They follow the folder of your last terminal prompt and, on macOS, of the Finder. Push never forces, pull only fast-forwards, and an AI CLI can write the commit message. English and French, following the system language.
- **A bubble for each coding agent**, with its mark: Claude Code, Codex, Gemini CLI and GitHub Copilot CLI. A click opens a terminal in the current project and starts `claude`, `codex`, `gemini` or `copilot`, on macOS and Windows, in the terminal set in `agent.terminal` (or `agent.launch`). An agent that is not found on the computer shows a grey bubble with "Install", and the click opens its install page instead. `agent.commands` changes the command line of one of them, e.g. `{ "codex": "codex --full-auto" }`. The marks are drawn by the plugin from SVG and belong to their owners. Without a current project, a click shows a notification.
- **Agent in project**, for any other agent or tool: it starts `agent.command`, `claude` by default.
- **Native vibrations on the MX Master 4** from the plugin: CI finished, review request, mention or assignment, pull request approved, merged, with changes requested or a failed check, git action result, focus and break over.
- **GitHub inbox** across all your repositories, through `gh api` only, with a clickable notification for each event. Each event can be turned off in `github.events`. Nothing is marked as read on GitHub.
- **Vulnerabilities for any stack** with osv-scanner (every lockfile of the repository), `npm audit` when osv-scanner is not installed. Scans again a few seconds after a lockfile changes. `audit.tool` picks `auto`, `osv` or `npm`.
- **Coding agent hooks** for Claude Code, Gemini CLI, Codex CLI and GitHub Copilot CLI: a vibration when the agent is done, waits for you or fails. The installers back up and merge `settings.json` and `hooks.json`, without jq on macOS. Copilot CLI hooks (`agentStop`, `notification`, `errorOccurred`) go to a file of their own, `~/.copilot/hooks/mx-dev-kit.json`, which the uninstallers delete: `hooks/install.sh --copilot`, `hooks\install.ps1 -Copilot`. The trigger file takes `claude`, `codex`, `gemini` and `copilot`.
- **Shell integration** for zsh, bash and PowerShell: project tracking, a vibration when a command longer than 30 seconds ends, `buzz` and `ci-watch`.
- **Scripts**: `haptic` plays a waveform, `mx-notify` shows a notification that opens a URL when clicked (the plugin carries it too), `uptime-watch` watches websites, health endpoints and local ports, `docker-watch` the containers of your compose project (dies, restart loop, healthy again).
- **Installers** for macOS and Windows 10/11: `curl -fsSL .../releases/latest/download/install.sh | sh` or `irm .../install.ps1 | iex`, or `mx-dev-kit.zip`. Nothing to build and nothing to install beyond Logi Options+. One question per part (plugin, agent hooks, terminal integration), `--only` / `-Only` to pick parts without asking, `--yes` for everything. Downloads are checked against `SHA256SUMS`, every edited file is backed up, and `uninstall.sh` / `uninstall.ps1` reverse it. `--from-source` builds the plugin from a clone, for contributors.
- **Releases** are built by `tools/build-release.sh`, the same script locally and in the release workflow, which also checks the package and the installers on Windows.
